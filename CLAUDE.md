# Project conventions

npm workspaces monorepo. `web/` is Next.js 16 (App Router, React 19, Tailwind v4, next-intl),
`studio/` is Sanity v6, `eslint-local-rules/` is the shared ESLint plugin. Locales are `he` (RTL,
default) and `en` (LTR).

## Layout and styling

- Logical properties only. Use `ms/me`, `ps/pe`, `start/end`, `text-start/text-end`,
  `border-s/border-e`, `rounded-s/rounded-e`. Never `ml`, `mr`, `pl`, `pr`, `left`, `right`,
  `text-left`, `text-right`, or an inline `direction` style. The `local/no-physical-direction` rule
  fails the build on these.
- Semantic color tokens only. Use the tokens defined in the theme layer, never a hex value, an
  `rgb()`/`hsl()` call, or a raw palette utility like `bg-slate-500`. Enforced by
  `local/no-literal-colors`.
- Every layout must survive a 390px viewport in both directions with no horizontal overflow.

## Copy

- No em dashes, en dashes, figure dashes or horizontal bars anywhere: UI strings, JSX text, content
  in Sanity, comments, docs. Use a comma, a colon, or a separate sentence. Enforced by
  `local/no-ui-dashes` in code, by `dashFreeDocument` at publish time in the studio, and by
  `npm run audit:dashes` against live content.

## Sanity data

- Every query lives in `web/src/sanity/queries/` and uses `defineQuery` with a globally unique
  constant name. Typegen keys off that name, so duplicates silently break types.
- Projections live in the fragments in `web/src/sanity/fragments/`, never inline in a query, so one
  block shape has one definition.
- `web/sanity.types.ts` is generated by `npm run typegen` and committed. Never hand edit it. Type
  components from the generated query result types instead of writing interfaces.
- Page builder items are keyed by `_key`, never by the array index.
- Heading level is a frontend prop decided by page position, not a schema field. Editors choose the
  text, the code chooses `h1` through `h4`.

## Stega and live preview

- `stega: false` on any client used for `generateMetadata`, `generateStaticParams`, sitemaps, robots
  and OG image routes. Encoded characters leak into head tags and route params otherwise.
- `stegaClean()` before comparing a string, using one as an object key, building an HTML id or an
  anchor, or passing a value to a third party (analytics, a form provider, a URL).
- Never `stegaClean()` text that is rendered, and never clean the input to PortableText or to the
  image url builder. That is what makes click to edit work.

## Routing

- Every internal href comes from `ROUTES` in `@/config/urls`, and reference links go through
  `resolveInternalHref`. No hardcoded string paths in JSX. Enforced by `local/require-url-builder`.
- Use the next-intl `Link`. It adds the locale prefix, so `ROUTES` returns unprefixed paths.

## Component structure

- A page file holds composition and copy only: fetch, then render blocks and primitives. Any markup
  worth reusing belongs in `components/primitives/` or `components/ui/`. Page and layout files are
  capped at 300 lines by ESLint.
- Blocks in `components/blocks/` are dumb renderers of one schema type, wired up through the
  `PageBuilder` switch.

## Before you push

`npm run lint`, `npm run typecheck`, `npm run test`, `npm run format:check`. Run `npm run typegen`
and commit the diff whenever a schema or a query changed.
